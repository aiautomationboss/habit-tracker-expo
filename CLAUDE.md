# CLAUDE.md — HabitTracker

Project context for Claude Code. Read this first before editing.

---

## 1. What this is

A polished React-Native habit tracker built on **Expo SDK 54**. It supports
recurring habits with per-day or per-quantity goals, schedule-aware streaks,
swipe + drag interactions, a retention pack (lapse / streak-at-risk / weekly
reflection / comeback), and a milestone celebration screen. The app runs in
**Expo Go** today; some features are wired but only fully reliable in a
**development build** (see §10).

It does **not** do tasks/to-dos. Habits and to-dos are different mental
models — see §11 if you're tempted to add one.

## 3. Routing model

`app/index.tsx` is a **declarative redirect gate**. It renders `<Redirect>`
after the zustand store has hydrated — this is critical: the previous
imperative `router.replace()` in `_layout.tsx` raced with the navigator
mounting and threw "Attempted to navigate before mounting the Root Layout."
Do not reintroduce imperative redirects from the root layout effect.

Tab paths use the `(tabs)` group; the entry tab is `/today` (renamed from
`index` to free up `/` for the gate).

Modals registered in `_layout.tsx`:
- `habit-form` — slide-up modal
- `day-detail` — slide-up modal
- `reflection` — slide-up modal
- `milestone` — full-screen fade modal

## 4. Data model

```ts
type HabitType = 'daily' | 'quantity';

interface Habit {
  id: string;
  name: string;
  type: HabitType;
  target: number;          // 1 for daily; per-day target for quantity
  color: string;
  icon: string;
  createdAt: string;
  order: number;            // drag-reorder index
  schedule: number[];       // 0=Sun..6=Sat; [] means every day
  reminder: { hour, minute } | null;
}

type Completions = Record<dayKey, Record<habitId, number>>;
type DayNotes = Record<dayKey, string>;
type Reflections = Record<weekKey /* Monday */, {
  worked: string; obstacles: string; intention: string; createdAt: string;
}>;

interface Challenge {
  id: string;
  title: string;
  habitIds: string[];
  durationDays: number;     // 3 | 7 | 30 | 365 (preset only)
  startDate: dayKey;
}
```

Date keys: always `yyyy-MM-dd` via `dateKey()`. Week keys for reflections are
the Monday of that week (`startOfWeek(date, { weekStartsOn: 1 })`).

### Store migration
`useHabits` is persisted with `version: 2`. The v1→v2 migration adds `order`,
`schedule`, `reminder`, `notes`. Bump the version + extend `migrate` when you
add fields.

### `partialize`
Don't accidentally persist `hydrated` or any derived selectors. Add new
persisted fields to `partialize` explicitly.

## 5. Schedule-aware streaks

`isHabitDue(habit, dayKey)` returns true if `schedule` is empty (= every day)
or the weekday is in `schedule`. **Rest days do not break streaks** — they're
*skipped* in `streak`, `bestStreak`, and `consistency`. Don't shortcut this
elsewhere; always use the store selectors.

`dayRatio(day)` divides done-due by total-due for that day, so days with no
due habits return 0 (not NaN), and the heatmap stays clean.

## 6. Reward loop

Triggered from `HabitRow` and `today.tsx` `handleComplete`:

1. **Haptic** — Success for normal complete; Warning + heavy impact at 7-day
   milestones.
2. **Sound** — `chime.wav` for single complete; `celebrate.wav` for all-done
   or milestone screen. Respects `soundsEnabled` from the store.
3. **Confetti** — `<Confetti ref/>` fired at the row's measured center
   (`measureInWindow`).
4. **Milestone screen** — `isMilestone(streak)` returns true at
   `[7, 14, 30, 50, 100, 200, 365]`. We `router.push('/milestone', { ... })`
   after a 600ms beat so the confetti on Today plays first.

If you change the milestone list, update `STREAK_MILESTONES` in
`src/lib/dashboard.ts`.

## 7. Notifications design (`src/lib/notifications.ts`)

One entry point: `syncNotifications()`. It cancels everything and
re-schedules from current store state. Call it after any change that affects
schedules: toggling the global reminder, changing global reminder time,
saving a habit, removing a habit, importing a snapshot, and once on app
hydration (root layout effect).

Schedules created by sync:
1. Global daily reminder at `reminderHour:reminderMinute` (if enabled).
2. Per-habit weekly trigger at `habit.reminder` time on each `habit.schedule`
   day (or all 7 if schedule is empty).
3. **Streak-at-risk** daily at 8 PM, only if any habit has current streak ≥ 3.
4. **Weekly reflection** weekly Sunday 8 PM.
5. **Lapse nudge** one-shot at next 9 AM if any habit's been silent ≥ 3 days
   (or was created > 3 days ago and never logged). Batched into one
   notification listing up to 3 habits with `(+N more)`.

Convention reminder: expo's WEEKLY trigger uses `weekday: 1..7` with
1=Sunday. Our internal schedule arrays use `0..6` with 0=Sunday. The helper
`scheduleWeekly(..., weekday0, ...)` does the `+1`.

## 8. Stats engine

### `src/lib/stats.ts`
- `rangeDayKeys(start, end)` — day keys, clamped to today.
- `completionStats(habits, completions, keys)` → `{ rate, perfectDays, trackedDays }`.
- `habitRate(habit, completions, keys)` → due/done ratio.
- `buildBuckets(habits, completions, start, end)` — chooses **day**, **week**, or
  **month** granularity automatically and returns labelled buckets for `<BarChart>`.

### `src/lib/dashboard.ts`
- `bestActiveStreak(habits, streakOf)` — used by Today hero. Only returns
  streaks ≥ 3.
- `weekStrip(dayRatio)` — last 7 days for the Today hero strip.
- `generateInsights({ habits, completions, dayRatio, consistency })` —
  templated insights for History. Returns up to 3.
- `STREAK_MILESTONES`, `isMilestone(n)`.

Insights are **rule-based templates**, not AI. Don't add Claude API calls
inside the daily app loop — costs/latency don't justify it. The right place
for AI is an opt-in "summarize my week" button on the reflection screen.

## 9. Theming

Three modes: `dark`, `light`, `system`. `useColors()` resolves system via
RN's `useColorScheme()`. All screens build dynamic styles with a
`makeStyles(palette)` factory called inside `useMemo`. Never import the
static `colors` export for app surfaces (it's there for backward compat
only) — always use `useColors()` so the theme toggle works.

When adding a new screen:
```tsx
const c = useColors();
const s = useMemo(() => makeStyles(c), [c]);
```

## 10. Known limitation: Expo Go notifications

Since SDK 53, expo-notifications' remote push has been removed from Expo Go
and **local scheduled notifications have known reliability issues**. The
retention pack (lapse, streak-at-risk, weekly reflection) is logically
correct but actual delivery is best-effort until a **development build**
(`npx expo run:android`) replaces Expo Go. The push-token warning at boot is
silenced via `LogBox.ignoreLogs(['expo-notifications: Android Push…'])` —
keep that, it's expected noise.

The dev build also unlocks home-screen widgets — those are deferred to that
phase.

---

## 11. Why no Tasks/To-Dos here

Tasks (deadline + status + done-once) and habits (recurring + streak) have
different mental models. Don't bolt tasks into this app — it would dilute
both. If you need a task manager, build it as a sibling app reusing this
shell (theme, store, navigation, notifications, time picker).

## 12. Running locally

```bash
# install deps (already done)
npm install --legacy-peer-deps

# start dev server (Expo Go)
npx expo start

# typecheck
npx tsc --noEmit

# verify the whole bundle compiles
npx expo export --platform android

# regenerate the two reward chimes (only if you change the script)
node scripts/gen-sounds.js
```

When `package.json` deps change, restart `expo start` cleanly with `-c`. Hot
reload survives most edits including theme switches.

## 13. Conventions

- **Files**: `kebab-case.tsx` for routes, `PascalCase.tsx` for components,
  `camelCase.ts` for libs.
- **Styles**: `makeStyles(c)` factory + `useMemo`. No inline `StyleSheet.create`
  at module scope for themed screens.
- **Store selectors**: name the selector arg `st` to avoid colliding with the
  conventional styles `s`. `useHabits((st) => st.habits)`.
- **Renames hurt expo-router**: tab files are at `(tabs)/<name>.tsx` and the
  Tab.Screen `name` prop must match. Changing one without the other 404s the
  route silently.
- **Don't import the static `colors`** for surfaces. Use `useColors()`.
- **Never call `router.replace()` from the root layout's effect** — see §3.

## 14. Reward audio assets

Both `chime.wav` and `celebrate.wav` are generated procedurally by
`scripts/gen-sounds.js` (no external assets). If you want different sounds,
edit the tone definitions there and re-run the script.

## 15. Backup format

JSON shaped like `Snapshot` in `src/types.ts`. Import replaces the store
(after confirm). Reflections are included. We use `expo-file-system/legacy`
because the new File/Directory API in SDK 54 is unstable in places — switch
to the new API only if Expo's docs clearly mark it as the recommended path
for your case.

## 16. What's NOT implemented (deliberately, for now)

- Habit **pause/archive** — discussed but skipped to keep the model lean. If
  added: add `archived: boolean`, filter from Today + Manage, keep in stats.
- **Finger-drag reorder** with autoscroll — current drag works inside a
  ScrollView but doesn't auto-scroll when dragging near edges. Real lists
  need `react-native-reorderable-list` or similar in a dev build.
- **Categories/tags** — overkill at typical habit counts (<15).
- **Subtasks** — habit-tracker antipattern; habits should be atomic.
- **Weekly target** ("3× per week without specific days") — different model;
  intentionally not in the type yet.
- **Streak freeze / skip day** — discussed; can be added with a `skipped`
  flag on the day record without breaking existing data.
- **AI-generated reflections** — see §8. Add only as opt-in.
